Источники читались в основном через поисковые сводки: прокси среды разработки закрывал первоисточники, поэтому цифры — порядок величины, а формулировки документации приведены по пересказам (см. «Ограничения» в конце каждого раздела). ### 1. Диагноз «robots.txt отдаёт localhost» был верен для кода до 05.10.2026, но в репозитории он уже исправлен: коммит ce89f54 добавил в src/app/robots.ts `export const dynamic = "force-dynamic"`, коммит da50ef4 добавил в GitHub Actions (check-site.yml) проверку, что боевой robots.txt содержит `Sitemap: https://<домен>/sitemap.xml` и не содержит `localhost`. Осталось: убрать поле `host` (Next.js печатает строку `Host: https://tr-rodionova.ru`, директива устарела) и убедиться, что исправление доехало до боевого сервера.

- Уверенность: high, приоритет P1
- Источник: https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots
- Основание: Проверено в репозитории 05.10.2026: `src/app/robots.ts` строка 5 — `export const dynamic = "force-dynamic"`, строка 35 — `host: base` (по-прежнему есть); `git log` — ce89f54 «GEO, шаг 4: robots.txt строится на запрос с боевым адресом…», da50ef4 «Check site: проверка, что robots.txt и llms.txt отдаются с боевым доменом»; ветка main синхронна с origin/main. `.github/workflows/check-site.yml` строки 50–53: `grep -q "Sitemap: https://$DOMAIN/sitemap.xml"` и `grep -qi "localhost"` → fail. Механизм исходной ошибки подтверждён: документация Next.js 16.3.8 (node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/robots.md, строка 22): «robots.js is a special Route Handler that is cached by default unless it uses a Request-time API or dynamic config option»; `.dockerignore` исключает `.env` и `.env.*`, `Dockerfile` делает `RUN npm run build` без APP_URL, `siteUrl()` в src/lib/seo.tsx падает на `http://localhost:3000`; в текущем `.next` записи /robots.txt в prerender-manifest больше нет. Сериализатор Next (dist/esm/build/webpack/loaders/metadata/resolve-route-data.js): `if (data.host) content += \`Host: ${data.host}\n\``. Отказ Яндекса от директивы Host (блог Яндекса, март 2018) — по памяти, в этом проходе страница не читалась. Боевой сайт из среды недоступен; результат проверки смотреть в Actions «Check site» после обновления сервера (docker-compose.yml: сервис web читает `.env` через env_file, поэтому APP_URL на запрос доступен).
- Что делать: 1) Удалить строку `host: base` из src/app/robots.ts (и, при желании, оставить комментарий, почему: Host не поддерживается Яндексом с 2018 г., другим ботам неизвестен). 2) Обновить сервер: `cd /opt/tr-rodionova && sudo -u deploy bash deploy/update.sh` (при автообновлении — в течение 10 минут). 3) Проверить: `curl -s https://tr-rodionova.ru/robots.txt` — должны быть две группы с одинаковыми Disallow и строка `Sitemap: https://tr-rodionova.ru/sitemap.xml`, без localhost и без Host; дождаться зелёного прогона GitHub Actions «Check site». 4) Проверить файл в Яндекс Вебмастере («Инструменты → Анализ robots.txt») и в отчёте robots.txt Google Search Console.

### 16. По RFC 9309 краулер обязан использовать группу, совпадающую с его токеном (регистронезависимо); несколько совпавших групп объединяются; группа `*` применяется только если совпадений нет. Поэтому отдельная группа `User-agent: GPTBot` / `Allow: /` без дублирования Disallow открыла бы боту /crm, /account, /checkout, /api/. Текущий src/app/robots.ts это учитывает: вторая группа из 22 токенов использует тот же массив PRIVATE, что и `*`; множественные строки `User-Agent:` в одной группе допустимы стандартом. Единственная правка — убрать `host`.

- Уверенность: high, приоритет P2
- Источник: https://www.rfc-editor.org/rfc/rfc9309
- Основание: rfc-editor.org, ietf.org и datatracker.ietf.org заблокированы — текст RFC в этом проходе не прочитан; формулировки §2.2.1 («Crawlers MUST use case-insensitive matching to find the group that matches the product token…»; «If more than one group matches the user-agent, the matching groups' rules MUST be combined into one group…»; «If no matching group exists, crawlers MUST obey the group with a user-agent line with the "*" value, if present») приведены по памяти стандарта и совпадают с исходным исследованием. Репозиторий 05.10.2026: `rules: [ { userAgent: "*", allow: "/", disallow: PRIVATE }, { userAgent: AI_AGENTS, allow: "/", disallow: PRIVATE } ]`, AI_AGENTS = YandexBot, YandexAdditional, YandexAdditionalBot, Googlebot, Google-Extended, Bingbot, GPTBot, OAI-SearchBot, ChatGPT-User, ClaudeBot, Claude-SearchBot, Claude-User, PerplexityBot, Perplexity-User, Applebot, Applebot-Extended, Amazonbot, Amzn-SearchBot, Meta-ExternalAgent, Meta-ExternalFetcher, DuckAssistBot, CCBot; сериализатор Next печатает по строке `User-Agent:` на токен, затем Allow/Disallow, затем `Host:` и `Sitemap:`.
- Что делать: Ожидаемый боевой robots.txt после удаления `host`: группа `User-Agent: *` с `Allow: /` и Disallow для /crm, /account, /checkout, /cart, /api/, /login, /register, /unsubscribe/, /go/; вторая группа с 22 строками `User-Agent:` и теми же правилами; пустая строка; `Sitemap: https://tr-rodionova.ru/sitemap.xml`. Если бренд выберет «цитирование — да, обучение — нет» — добавить третьим элементом `rules` объект `{ userAgent: ["GPTBot", "ClaudeBot", "Google-Extended", "Applebot-Extended", "Meta-ExternalAgent", "CCBot"], disallow: "/" }` и убрать эти токены из AI_AGENTS (иначе две группы для одного токена объединятся и Allow: / перекроет запрет по правилу длиннейшего совпадения). Поисковые и пользовательские агенты не трогать. Проверить результат валидатором Яндекс Вебмастера и отчётом robots.txt в Google Search Console.

## content — форматы контента, которые ИИ-ответы цитируют чаще, и как применить их к tr-rodionova.ru (товары, журнал, FAQ, «О бренде», «Доставка», «Размеры») — после скептической проверки

### 1. Прямой ответ должен стоять в начале страницы и в начале каждой секции: ИИ извлекает дискретные фрагменты, а не страницу целиком, и чаще берёт их из верхней части текста. Величина эффекта («44,2% цитат из первых 30%») — из непроверенного вторичного пересказа.

### 2. В статьях о тканях давать проверяемые числа только с реальным источником (паспорт ткани от фабрики, ГОСТ, собственный тест) — никаких «правдоподобных» ссылок. 1–2 именованные цитаты Татьяны Родионовой на статью — как сигнал авторства (см. ### 3. Формат «вопрос — ответ» и чёткая секционная структура удобны для извлечения фрагментов и, по вендорским корреляциям, связаны с цитированием. Утверждение «FAQ цитируются чаще карточек» опирается на опрос мнений маркетологов, а не на измеренные цитаты.

Утверждение о доминировании Quora среди источников Google AI Mode — из исследования Semrush по AI Mode (2025), не перепроверено. Проверено в репозитории: /faq уже отдаёт ответ первым предложением (src/lib/faq.ts), FAQPage есть на /faq и карточках; на карточке 4 вопроса (размеры, уход, доставка, возврат); у 3 из 13 ответов на /faq нет ссылки «Подробнее» (предзаказ, оплата, скидки).

На карточках расширить productFaq с 4 до 6–8 вопросов (посадка, рост и размер модели на фото, плотность ткани, срок доставки в город, как проходит примерка курьером, что входит в цену) — данные брать из полей товара и настроек, не вшивать. На /faq группировка по намерениям уже есть (4 группы); добавить href ко всем ответам без ссылки. Не ждать от FAQ-разметки расширенных сниппетов в Google (см. отдельную находку).

### 4. Длина сама по себе не предсказывает цитирование; важнее покрытие конкретных подтем и фокус одной страницы на одном запросе.

- Уверенность: medium, приоритет P2
- Источник: https://ahrefs.com/blog/short-vs-long-content-in-ai-overviews
- Основание: Ahrefs, «Short vs. Long Content in AI Overviews» (2025): корреляция длины и цитирования 0,04 (Спирмен), 53,4% цитируемых страниц короче 1000 слов — цифры из пересказа, статья в сессии недоступна. Kevin Indig (2026, 815 000 пар запрос–страница): лучше цитируются страницы, покрывающие 26–50% подтем; главный предиктор — позиция в поисковой выдаче ChatGPT — не перепроверено. Длинные статьи («Чёрный total look», «Хранение между сезонами», «Вискоза в трикотаже») проверить на самодостаточность секций. Новые темы планировать по реальным вопросам покупательниц и отчёту Вебмастера «Показы сайта в Алисе AI», а не по принципу «ultimate guide».

### 5. Редакторское правило «один абзац — один вопрос — один явно названный субъект» — практическая эвристика для извлекаемости фрагментов; конкретные границы «40–80 слов» исследованиями не подтверждены.

- Основание: Lilach Bullock (2025–2026): рекомендация 40–60 слов на абзац, «длиннее ~80 слов ретривер режет посередине» — мнение практика без данных, первоисточник недоступен. Косвенная поддержка — вывод Semrush, что ИИ «приоритизирует дискретные фрагменты контента», и верхнее расположение цитат у Indig (оба не перепроверены). Проверка: понятен ли абзац отдельно от страницы. Не тратить время на подсчёт слов.

### 6. ИИ-ассистенты в среднем цитируют более свежие страницы, чем органика Google; поддерживать актуальность содержательными правками с видимой и машинной датой. Менять дату без реальных правок Google прямо относит к «контенту для поисковиков».

GEO-16 (arXiv 2509.10762, сентябрь 2025) — выборка 70 промптов B2B SaaS, не перепроверено, доказательная сила низкая. Обновлять «Доставка», «Размеры», «Уход» при каждом изменении тарифов или ассортимента. Подключить IndexNow из CRM при публикации/правке (Яндекс и Bing поддерживают протокол; Google — нет).
