# Реклама: Яндекс Директ из CRM

CRM управляет кабинетом Директа по API v5 как директолог: создаёт кампании, запускает и останавливает,
меняет бюджеты, ведёт A/B-тесты текстов, добавляет минус-слова, собирает статистику и считает CAC по реальным заказам.
Раздел: CRM → Реклама (`/crm/ads`). Подключение: CRM → Интеграции → Реклама → Яндекс Директ.

## Что нужно от владельца (один раз)

1. Кабинет Директа под логином владельца. В кабинете: Инструменты → API → заявка на доступ к API (одобряют за 1–2 дня).
2. OAuth-токен с правом «Яндекс Директ: использование API» — oauth.yandex.ru → «Создать приложение» →
   платформа «Веб-сервисы», Redirect URI `https://oauth.yandex.ru/verification_code`, права Директа (и Метрики, если одно приложение).
   Затем `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` → скопировать `token` из адресной строки.
3. Токен вводится только в CRM (поле зашифровано в базе), целевая стоимость заказа — рядом. «Проверить подключение»
   показывает логин кабинета, валюту и остаток баллов API; код 54 — заявка на API ещё не одобрена.
4. Доступ логина Директа к счётчику Метрики (Метрика → Настройки → Доступ) — иначе кампании создаются без счётчика,
   ретаргетинг и оплата за конверсии недоступны. В интеграции Метрики нужен OAuth-токен: он создаёт цели с флагом «ретаргетинг».
5. Баланс пополняется только в кабинете Директа. CRM к деньгам доступа не имеет.

## Стартовый набор

Форма в разделе «Реклама»: месячный бюджет, целевая стоимость заказа, регионы (Москва и область, Санкт-Петербург и область,
вся Россия), какие кампании создать. Бюджет делится: бренд 10 %, ретаргетинг 20 %, остальное поровну между категориями;
недельный бюджет стратегии не меньше 300 ₽ (минимум Директа).

| Кампания | Что внутри |
| --- | --- |
| TR · Бренд · Поиск | фразы по названию бренда, два текста, быстрые ссылки |
| TR · <Категория> · Поиск | 7–10 фраз на категорию (`src/lib/ads/starter.ts`), автотаргетинг (точные и альтернативные запросы), два текста с ценой «от …» и тканью из карточек, общий список минус-слов |
| TR · Ретаргетинг · Сети | условие «смотрела вещь 30 дней и не заказывала 90 дней» по целям Метрики `product_view` и `order`, два текста, фото образа |

Стратегия «максимум кликов» с недельным бюджетом, счётчик Метрики и приоритетная цель «заказ». Все кампании создаются
на паузе; кнопка «Запустить все на паузе» в шапке раздела. UTM: `utm_source=yandex&utm_medium=cpc&utm_campaign=direct-<slug>`,
по ним собственная аналитика привязывает заказы к кампании.

## Ежедневный цикл (`runDailyJobs` → `syncAds`)

1. Зеркало кампаний кабинета в `AdCampaign` (созданные не из CRM видны как «создана в кабинете», оптимизатор их не трогает).
2. Статистика за 7 дней из `CAMPAIGN_PERFORMANCE_REPORT` в `AdStat` (копейки с НДС); по кнопке «Обновить статистику» — 30 дней.
3. Оптимизатор (`src/lib/ads/optimizer.ts`), окно 14 дней:
   - A/B-тест: в группе два текста; при ≥500 показов у каждого и ≥15 кликов у лидера вариант с CTR ниже на 40 % останавливается;
   - кампания потратила ≥3 целевых CPA без заказов — бюджет −30 %; ≥6 — пауза (брендовая — только по подтверждению);
   - CAC ≤ 70 % цели и ≥3 заказов — бюджет +25 %, не выше ×1,5 от плана;
   - нецелевые поисковые запросы (выкройки, детское, маркетплейсы, б/у, фото, оптом…) с кликами без конверсий — в минус-фразы;
   - ≥10 конверсий за 30 дней — рекомендация перейти на оплату за конверсии (по подтверждению).
   Уровни: «автопилот» применяется сам (если в интеграции не написано «нет»), «нужно подтверждение» — кнопка «Применить».

Результат последнего прогона хранится в `Setting` `ads.optimizer`; все действия пишутся в журнал (`ads.*`).

## Права

`ads` (менеджер, администратор) — смотреть статистику, обновлять, рекомендации. `adsEdit` (администратор) —
создавать и запускать кампании, менять бюджеты, применять рекомендации: всё, что тратит деньги.

## Стенд

`DIRECT_API_BASE=http://127.0.0.1:3399/json/v5` подменяет адрес API локальной заглушкой (только для проверки).
